## 根因和修复

1. 原统计把 `agentmux.internal` 的 Codex 请求标为 CLI。现在请求来源优先于线程创建来源：内部调用独立显示，正常 CLI、Desktop、IDE 与未知来源保留各自分类。通过 AgentMux 代理路由的外部 CLI 请求仍归 CLI。
2. 内部实时记录与同一会话的 rollout 被重复计入。报表按同机、会话、模型和所有 Token 分项，在 60 秒内一对一归并。保留未匹配尾部、不同请求与重试，原始账本不删除。代理转发采集的请求也与对应 rollout 一对一归并，仍保留外部客户端分类。
3. rookie-trade 使用 `codex exec --ephemeral --json`，不会留下普通 rollout，成功 stdout 原先直接丢弃。现在从 `thread.started` 和 `turn.completed.usage` 保存仅含用量的原子回执，不写入提示词或模型回答。成功、输出校验失败和超时前已完成轮次都会保存。存储失败只记警告，不中断业务。
4. 采集范围扩展到 `archived_sessions` 和 `$CODEX_HOME/usage/agentmux-exec`，默认 `CODEX_HOME=~/.codex`。回执使用调用 ID + 轮次编号去重；重放幂等，重试分别计量。
5. 原数据库以会话和时间戳作为所有记录的主键，多个有独立请求 ID 的记录在同一时间戳会冲突。迁移 18 保留原数据，改为请求记录和传统日志各自的唯一索引；SQLite 兼容迁移也验证了数据保留与重复打开。
6. 页面把“精确覆盖”改为“已记录量精确占比”，并明确未保存用量的 CLI 调用不计入，避免将来源计数精确误读为采集完整。

## 覆盖限制

历史成功的 ephemeral 调用没有保存 stdout，无法精确恢复。未完成或被强杀且没有 usage 的请求也没有足够证据，因此当前数字是已记录量，不代表全部真实消耗，不把缺失值填零。CLI 回执是完成轮次的合计，可能含多个模型请求，不能恢复精确模型请求次数。回执时间为子进程返回时间，模型标签为调用方指定值。

缓存 input 是总 input 的子集，reasoning output 已含在 output 中，均不重复累加。本次核对只验证 Token，没有把离线重放使用的价格当作实际账单。
